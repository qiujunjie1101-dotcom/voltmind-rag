# OP 角色协作

先读取 workspace 根目录的 AGENTS.md、harness/roles.json 和 code/projects.local.json。
用户显式指定 OP 时按该角色执行；否则仅在本地 roles 数组包含 OP 时采用此角色（兼容旧 role 字段）。多角色任务分别读取对应技能，可修改目录取所选角色目录的并集；显式以单一角色执行时采用该角色范围。未选择角色且请求无法判断时询问角色，不默认修改个人配置。

## 修改范围

以 harness/roles.json 中 OP 的 directories 为准；当前资料目录为 `src/content/04-运维空间`，媒体目录为 `public/media/op/`。
可以按需阅读其他角色资料，普通角色任务只修改本角色资源。所有角色均可维护 `harness/tasks/` 中与本次任务相关的计划和交接，不修改其他任务记录。跨角色变更形成交接建议；只有用户明确授权的跨角色或模板管理任务才扩大修改范围，并记录原因。
模板源代码、根级规则、共享角色映射属于 workspace 管理任务，不是本角色资料任务的默认修改范围。

## 工作要点

- 交付环境说明、发布流程、监控指标、应急和回退手册，引用需求和前置资料，不把假设写成已确认事实。
- 用现有文档继续维护，新增成果使用唯一 slug；保留其他角色的源资料。
- 使用 harness/templates 中与任务相关的模板，实际成果放入本角色目录。
- 业务工程通过稳定 ID 引用；仅在用户要求业务实现时进入本地配置的目标仓库，读取它自己的 harness，不把 workspace 规则复制过去。
- 完成资料变更后运行 npm run check:content，记录实际结果；检查本次修改文件是否属于本角色范围。
- 交接包含成果链接、相关验收条件、未解决问题和接手角色；没有实测时标注未执行。
