## 这份资料能帮你做什么

这篇教程保留了模板早期以 AI2CC 为临时品牌时的搭建方法与原始 Prompt，属于历史参考。**当前项目是 Ai Workspace 通用基础模板，Slogan 为“ai研发知识管理空间”**；下文中的 AI2CC 品牌、社区主题和参数默认值不代表当前定位，也不应直接作为新项目资料。直接复用当前工程请先阅读 [Workspace AI 新范式介绍](../02-Workspace-AI新范式介绍.md)。

如需从零重建同类知识库，可复制文末完整 Prompt，替换品牌与用途后交给能够创建项目、运行终端和检查网页的 Coding Agent，**不需要 ZIP、已有源码或必须另附的截图**。

历史 Prompt 默认沿用早期 AI2CC 的紧凑布局、浅深色主题、Markdown 阅读和本地编辑功能。品牌名、Logo、Slogan、配色、正文宽度、目录间距等都可以通过参数或设计问答调整。

> 这里保存的是可复用的搭建要求，不是已经完成新项目的证明。Agent 生成项目后，仍需要实际构建和浏览器验证；仅凭文字也无法保证与原始品牌 PNG 逐像素一致。

## 三步开始搭建

1. 跳到[完整 Prompt](#完整-prompt)，点击代码块右上角的 **复制**，复制整段内容。
2. 在新的项目目录或新的 Coding Agent 对话中粘贴并执行。你可以直接回答 Agent 的设计问题，也可以先填写 `USER_OVERRIDES`。
3. 根据 Agent 返回的本地地址查看页面，检查目录、主题、Markdown 预览和本地保存，再开始替换自己的内容。

如果想沿用默认设计，在发送 Prompt 时补充一句：**“全部设计参数使用默认值，直接开始搭建。”** 这样 Agent 可以跳过设计问答。

只想修改当前知识库内容时，直接参考[内容写作指南](./01-内容写作指南.md)和[本地编辑与媒体](./02-本地编辑与媒体.md)，无需重新搭建。

## Agent 会先问什么

没有预先指定设计时，Prompt 要求 Agent 使用当前环境实际提供的提问组件，通常先问三组信息：

| 问题 | 可以补充的内容 | 默认方案 |
| --- | --- | --- |
| 品牌信息 | 网站名称、Slogan、知识库主题 | AI2CC、AI to Coding Community |
| 品牌素材 | 自动字标、已有 Logo，或纯文字；是否需要首页横幅 | 自动生成字标和横幅 |
| 视觉偏好 | 主题色、浅深色偏好、布局尺寸、字体密度 | 蓝色强调色、紧凑布局、首次跟随系统 |

不同 Agent 可能提供 `AskUserQuestion`、`request_user_input_async` 等不同工具。Prompt 会要求按真实工具能力调用；没有可用组件时才用文字提问。已经填写或回答的字段不重复问。**这些问答发生在 Agent 对话中，不会成为网站里的问卷。**

## 常用参数怎么改

完整 Prompt 顶部的 `USER_OVERRIDES: {}` 是自定义入口。只写需要修改的字段，其他部分保留默认配置。

```yaml
USER_OVERRIDES:
  site:
    name: "我的知识库"
    slogan: "Build, Learn, Share"
    topic: "个人技术实践与学习笔记"
  brand:
    logoMode: "generated-wordmark"
    bannerMode: "generated"
  theme:
    preset: "teal"
    initialMode: "system"
  layout:
    articleMaxWidth: 760
    tocGap: 112
```

| 参数组 | 主要用途 | 常用字段 |
| --- | --- | --- |
| `site` | 名称与内容定位 | `name`、`slogan`、`topic`、`docsLabel` |
| `brand` | Logo、横幅与尺寸 | `logoMode`、`logoLightSource`、`bannerMode`、`logoWidth` |
| `theme` | 配色与首次显示模式 | `preset`、`initialMode`、`light.primary`、`dark.primary` |
| `layout` | 页面比例与间距 | `sidebarWidth`、`articleMaxWidth`、`tocGap`、`contentMaxWidth` |
| `typography` | 正文与目录密度 | `bodySize`、`bodyLineHeight`、`navSize`、`navRowHeight` |
| `appearance` / `motion` | 圆角、图标和过渡 | `radius`、`iconStrokeWidth`、`enabled`、`sidebarDuration` |
| `content` | 初始文档 | `welcomeTitle`、`sampleCount`、`categories` |

主题预设有 `ai2cc-blue`（蓝色）、`monochrome`（黑白中性）、`teal`（青绿）、`violet`（紫色）。`initialMode` 可设为 `system`、`light` 或 `dark`。

Logo 可选择 `generated-wordmark`（自动字标）、`text`（纯文字）或 `provided`（使用已提供素材）；横幅可选 `generated`、`provided` 或 `none`。选 `provided` 时，需要向 Agent 提供实际可读取的素材来源。

Prompt 要求生成的项目把最终参数集中到 `src/site.config.ts`，以后改品牌或布局时有明确入口。**这是历史教程对新生成项目的实现要求，不代表当前 Ai Workspace 已经迁移到这份配置文件。**

## 怎么确认搭建完成

拿到 Agent 的结果后，至少检查：

- 页面在桌面和手机宽度下可以正常阅读，没有页面级横向滚动。
- 左侧目录能多层展开，整个侧栏收起后仍能重新打开。
- 浅深色切换、刷新保持、代码高亮和复制、右侧标题目录可以使用。
- 在支持本地目录 API 的浏览器中，新目录、Markdown 和媒体真正保存到了选定项目。
- Agent 实际执行了构建和内容检查，并说明不能在当前环境验证的项目。

默认设计按 Prompt 中的坐标和色值验收；修改参数后，按最终配置核对，不再强制使用原默认坐标。完整功能与边界可对照[知识库技术方案](../../03-技术空间/01-架构设计/01-知识库技术方案.md)。

## 使用范围与限制

这是一份从零生成工程的 Prompt。不同 Agent 的工具能力和实现质量可能不同，不能只凭一句“已完成”判断功能全部可用。目前这份参数化 Prompt 已完成参数语法和规则一致性检查，尚未作为独立新项目完整运行验收。

纯前端写入真实本地目录需要浏览器提供 File System Access API，并由用户选择和授权项目文件夹。不支持该 API 的环境仍可阅读，不能靠 Prompt 绕过浏览器能力限制。

自动生成的 SVG 品牌素材不等于当前原始 PNG；如果需要使用自己的确切 Logo，可以选择 `provided`。跨操作系统的字体和文字抗锯齿也可能不同。修改本地文件不会自动更新线上站点，发布时仍需重新构建。

C. 必须使用 Agent 实际提供的提问组件

1. 先读当前会话和 USER_OVERRIDES，只问缺失的设计偏好，不重新询问已明确的名称、Logo、颜色或尺寸。若用户明确说“全部默认、直接开始”，或其覆盖参数已完整说明设计并授权其余默认，跳过问答直接执行。
2. 检查当前 Agent 的工具列表和调用规则，优先调用环境实际可用的结构化提问组件。名字可能是 AskUserQuestion、ask_question、askquestion、request_user_input、request_user_input_async 等，但不得假设某个名字必然存在；按真实 schema 调用，并遵守模式限制。例如只在 Plan 模式可用的工具，不能在 Default 模式强行调用。
3. 不能仅在回复里写一个伪工具调用、工具名或 JSON 代替真实调用，也不为此安装组件或修改网站。环境完全没有可用提问工具时，才用简短的普通文本一次性问清。
4. 第一轮最多三个问题，已知的略过。支持一次多问就合并为一次调用；支持有限选项就遵守真实工具数量限制。每题保持简短，有明确默认方案，用户可自由补充：
   - 品牌信息：用自由输入询问网站名称、Slogan 和内容主题，展示当前默认值；允许只回答想修改的字段，或回复“沿用默认”。不要让用户填写一份巨大表单。
   - Logo 和首页横幅：优先提供“自动生成品牌字标与横幅（推荐）”“我有现成品牌素材”“纯文字品牌，不显示横幅”。已有用户素材信息时直接使用，必要时只补问未说明的横幅偏好。自动方案设 logoMode=generated-wordmark、bannerMode=generated；纯文字方案设 logoMode=text、bannerMode=none。
   - 视觉：提供“AI2CC 蓝色，当前紧凑布局（推荐）”“黑白中性，当前紧凑布局”“自定义颜色或尺寸”。选黑白只改 theme.preset；自定义时进入下面的一次针对性补问。用户如果只能选两项，就保留默认与自定义，其他偏好可自由输入。
5. 用户选自定义或需要补充素材时，最多再一轮、最多三个必要问题：主题色/首次浅深色偏好；侧栏与正文宽度/目录间距/字体密度；素材来源与用途。只补问用户要改的部分，未提及的数值继续沿用默认，不要求所有字段逐一回答。允许用户用“青绿、稍宽松”这类描述表达设计意图。
6. 问题工具如果只支持文本，不要要求它上传文件或截图。只询问用户是否有当前会话已附的素材，或其路径/URL；用户想新增附件时，按照宿主实际支持的附件流程说明。provided 模式在素材缺失时，不静默替换成自动生成；向用户提供改用自动方案或补齐来源的选择。
7. 如果是异步提问工具，发出后可以检查环境、初始化与设计无关的工程部分，但在收到回答前不要定稿品牌素材和视觉实现。预选项未提交、超时或无返回值都不等于用户已选择默认。同步工具需等待真实回答；遵守宿主对无返回值情况的更高优先级规则。
8. 拿到回答后，用 3–5 行陈述解析结果，例如“品牌 XX；自动字标；青绿强调色；正文 760px；其余采用紧凑默认”，然后开始实现，不再追加一次泛泛的“确认开始”。如果用户先前已授权默认，无需为了走流程重复提问。

D. 参数解析规则

- 项目名/名称有不同用途：site.name 可为中文和长标题；site.projectId 仅作为目录、npm 名称和存储命名空间，使用合法的 ASCII kebab-case，无法从品牌名可靠派生时用 docs-site。用户明确更改品牌而未设置 projectId 时自动派生，不遗留 ai2cc-docs。项目创建后 projectId 保持稳定，未来仅修改显示名称不能使浏览器保存的目录授权丢失。
- storageNamespace=site.projectId；localStorage 主题 key=`${storageNamespace}-theme`；IndexedDB 名=`${storageNamespace}-local-project`；store=handles、key=project；目录 picker id 使用稳定、短且合法的 `${storageNamespace}-project`（满足浏览器长度/字符限制）。这些值由配置统一生成。
- theme.preset 的默认 primary（浅/深）：ai2cc-blue=#3f5dc1/#91a9ee；monochrome=#343a46/#cad2e2；teal=#187a70/#7ccfbe；violet=#7250ad/#bd9cf0。浅色主按钮字默认为白色，深色主按钮字默认为 #181a1f；用户自选颜色时计算对比度选择合适前景。
- 未改色的 ai2cc-blue 保留后文精确配色。更换 preset/primary 时同步生成链接、导航选中、hover、focus ring、TOC 活动线、引用块强调线和选中浅底的语义色；保留中性底色和文本层级。不能只改按钮颜色，其他状态仍遗留默认蓝色。用户改背景/文字/边线时，面板、表单、代码块也从新基础色派生协调的中性色，保证可读性；语法高亮可保留独立多色体系。
- 用户说“稍宽松”且无更精确值时：navRowHeight=30、navRowHeightMobile=34、navSize=13、bodySize=15、bodyLineHeight=1.9；其他几何不变。明确给数值时优先用用户值。默认“紧凑”就是 DEFAULTS。
- 主尺寸变化时，联动计算依赖值：aside top=headerHeight，aside height=100dvh-headerHeight，按钮 top=headerHeight+15、left=sidebarWidth-14（中屏使用 sidebarWidthMedium）；TOC sticky top=headerHeight+32；标题 scroll-margin-top=headerHeight+24；面包屑/阅读区对齐。长品牌或较大字号用自适应布局处理，不通过裁掉正文或产生横向滚动满足固定宽度。
- 圆角派生：主面板/媒体/代码块使用 appearance.radius，小控件 radiusSmall=max(0,round(radius/2))，输入框 radiusField=max(0,radius-2)。图标描边统一来自 appearance.iconStrokeWidth。尺寸变量不应只存在于配置声明而没有被组件消费。
- 断点满足 breakpointMobile < breakpointHideToc < breakpointMedium。尺寸需为有限正数；字号、宽度极端到破坏阅读或无法满足布局时说明具体冲突并询问相关字段，不静默恢复默认。自定义后的验收使用解析后的配置与计算几何；后文固定坐标仅用于 DEFAULTS。
- 首页 Banner 只在 homeSlug 指定文档且 bannerMode 不为 none 时显示；其比例按 bannerWidth/bannerHeight。隐藏横幅时正文顶部仍保持原容器位置，h1 自然占据内容起点，不保留假图片占位。
- 自定义图片使用用户授权的素材；可复制到本地静态资源目录以供运行时离线使用，不把本地绝对路径直接写进最终网页。有明暗两版就分别使用；只有一张彩色图时保留颜色，必要时加中性底板提升可读性，不随意 invert。

E. 参数必须真正落地

【七、内容解析和阅读】

src/lib/content.ts 负责以下纯函数和响应式集合：parseDocument、renderDocument、buildKnowledge、resolveMarkdownLink、mediaSources、docHref、replaceKnowledge，以及 docs 和 navigation。

用 import.meta.glob('../content/**/*.md',{query:'?raw',import:'default',eager:true}) 导入正文；目录真实层级生成导航。以路径 localeCompare('zh-CN',{numeric:true}) 排序；显示名去掉开头数字及紧邻的 - 或 .、去掉 .md。扫描 .gitkeep 保留空目录。

YAML frontmatter 字段 title、slug、description、date、status；slug 唯一且用于稳定链接；title 默认文件名；slug 默认相对路径；status 默认“草稿”；date 存字符串。
首页至少有一篇 title 取 content.welcomeTitle、slug 取 content.homeSlug。正文从 ## 开始，h1 由页面渲染。准备 content.sampleCount 篇合理的初始文档，分类取 content.categories、内容围绕 site.topic；可自拟内容，但不能把假设写成已完成调研。至少有三层嵌套、代码、表格、引用、列表和中文标题例子。

路由格式 #/encodeURIComponent(slug)，标题深链加 ?heading=encodeURIComponent(id)。监听 hashchange，支持前进/后退。文章切换滚动顶部，标题深链定位标题。文档不存在和空文档集有不同的空状态。

markdown-it 设置 html:false、linkify:true、typographer:true。markdown-it-anchor 处理 h2/h3，slugify 为 trim/lowercase/空白转短横线并处理重复标题。highlight.js/lib/common 高亮已知语言，未知语言必须 escapeHtml。

将 Markdown 相对 .md 链接、.md#锚点和同文档 #锚点解析为真实 hash href，保留 Cmd/Ctrl 点击打开新标签页能力，不只靠 click 事件模拟路由。外部 URL 保留。
TOC 仅列 h2/h3，IntersectionObserver 用 rootMargin:'-90px 0px -65% 0px' 更新活动项，点击滚动到目标。
代码复制按钮读取 code.textContent，成功显示“已复制”约 1800ms；失败提示手动复制。标题元信息提供复制整页链接、编辑；底部上一篇/下一篇按排序生成。

【八、浅深色与可访问性】

主题状态为 html[data-theme="light"|"dark"]，localStorage key 从 storageNamespace 派生。首次无保存偏好时按 theme.initialMode：system 用 prefers-color-scheme，light/dark 用指定模式；存在保存值时优先恢复。index.html 的 head 内脚本在应用挂载前初始化，避免白屏闪烁；存储访问用 try/catch，存储不可用仍能切换；color-scheme 同步。移动端与编辑抽屉全部适配。

图标按钮必须 aria-label；折叠按钮 aria-expanded/aria-controls；当前文档 aria-current=page；保存通知 role=status，错误 role=alert。隐藏侧栏 inert；保留可见 focus-visible 边框、“跳到正文”、Dialog 焦点控制和 Escape 行为。通过事件监听添加的 Observer/监听器在卸载时清理。

【九、本地编辑，必须真实写所选项目】

使用 File System Access API，从用户点击触发 showDirectoryPicker({id:pickerId,mode:'readwrite'})，其中 pickerId 由配置按前述规则解析。校验所选项目含 package.json 和 src/content。文档写入 src/content，媒体写入 public/media。目录操作范围必须限定在用户所选根目录，校验名称和路径，禁止 .. 路径穿越。

handle 存 IndexedDB：库名由 storageNamespace 派生，store handles，key project。刷新时仅在 queryPermission 已 granted 时自动恢复；需要授权时由重新连接按钮触发。存储不可用仍允许本次会话连接。

不支持目录 API 的浏览器显示“当前浏览器不支持文件夹读写，请使用桌面 Chrome 或 Edge 打开本地知识库”；仍可正常阅读。不能通过 polyfill 绕过浏览器权限，不把 localStorage、OPFS、下载 ZIP 或后端代理冒充对原项目的写入。

编辑器按需 defineAsyncComponent 加载。右上角本地编辑、正文编辑、左侧加号共用 LocalEditor。右侧 Sheet 宽 min(1120px,96vw)，max-width:none，高100%，padding:23px 26px 18px；标题 16px；关闭按钮右上。未连接时显示简洁的目录选择说明和按钮。
连接后支持创建目录、选择父目录创建 .md、编辑已有 Markdown；空目录创建 .gitkeep；文件名过滤路径分隔符和非法字符；重名和重复 slug 提示。
新文档 frontmatter 包含 title、随机唯一 slug、字符串日期、status:草稿。文件名变化同步 title。
顶部工具条有文件路径、插入媒体、源码/双栏/预览切换。双栏默认各50%；最小高度220；源码 textarea 12px/1.85 等宽字体、padding:18px 19px，预览 padding:20px 24px，独立滚动；预览调用与阅读页面相同 renderer，链接不跳离草稿。
移动端 Sheet 宽100vw，padding:20px 15px 16px，字段单列，双栏变上下两行。
底部有重新读取、重新连接、“仅保存到本地，线上更新需重新发布”、保存按钮。支持 Cmd/Ctrl+S，未保存标记、关闭/换模式/重读前确认、beforeunload 提醒。保存过程中禁用/inert 所有可编辑控件、阻止关闭，避免丢草稿。

【十、图片视频与保存一致性】

支持 ClipboardEvent.clipboardData.files 粘贴、DragEvent.dataTransfer.files 拖入、input[type=file] 多选。只粘贴文本 URL 时保留文本，不自动下载；视频来源没提供文件数据时说明可选文件。图片支持 PNG/JPEG/WebP/GIF/AVIF，视频 MP4/WebM/OGV/MOV；拒绝 SVG 等未列入的插入文件。

生成 crypto.randomUUID() 文件名，保留真实扩展名与原字节。插入时仅将 File 与 Blob URL 暂存内存，预览用 Blob URL；只有点保存才写 public/media；取消或卸载释放 URL。未经引用的暂存媒体不写盘。

插入 Markdown 示例：
![图片说明](./media/唯一ID.png "width=640")
![视频说明](./media/唯一ID.webm "width=640 height=360")

提供媒体下拉选择、宽度 px、可留空的高度 px、“应用尺寸”“自适应”；数值限制1–4096，默认宽640，高auto。renderer 额外支持安全百分比宽度，但禁止任意 CSS 注入。
图片输出 img；视频按原路径扩展名识别后输出 video，controls、playsinline、preload=metadata。禁止 autoplay、iframe；max-width:100%，明确 height 时 object-fit:contain。尺寸仅影响显示，不压缩/重采样/上传原文件，播放格式取决于浏览器解码能力。

保存时先读取磁盘原文，和编辑器打开时的 baseline 比较；已有外部修改则保留当前草稿并提示合并，不静默覆盖。先验证最新文档集的 YAML/slug，再写仍被引用的暂存媒体，最后写 Markdown。写媒体后、写文档前再次检查磁盘变化，新文档同名冲突同样拒绝。
写入用 createWritable，异常时 abort；文档提交前失败只回滚本次新建文件。已有文件和媒体不能被回滚删除。文档已写入但列表刷新失败时区分提示“文件已保存，但列表刷新失败”，更新 baseline，不把已保存内容假报为未保存。
刷新目录后更新响应式 docs/navigation、读取本地资源生成 Blob URL，正确释放旧 URL。当前主题与编辑状态保留。
Vite 为 src/content 新增/修改/删除配置内容模块 self-accept HMR，更新文档集合，避免整个页面刷新而丢掉编辑草稿；可用 post hotUpdate 将文件事件导向内容模块。此插件仅用于热更新，不提供写文件 API。
