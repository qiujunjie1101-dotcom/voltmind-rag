## 定位与范围

`voltmind-web/` 是 VoltMind 的前端工作台，技术选型见《[技术架构](../01-架构设计/02-技术架构.md)》。

对话页接入 Python AI 服务，知识库页接入 Java 业务服务。知识库与文档列表、统计、上传和删除均来自真实接口；文档解析、向量化、RAG 与知识检索尚未实现。

## 布局结构

工作台采用「左侧导航 + 右侧内容区」两栏结构。

| 区域 | 内容 |
| --- | --- |
| 左侧导航 | 品牌标识、分组导航、主题切换与运行状态 |
| 右侧顶栏 | 移动端导航按钮、当前页标题与描述、接入状态标记 |
| 右侧内容区 | 按导航切换视图，独立滚动 |

导航分三组：**工作台**（对话、知识库）、**规划中**（文档入库、检索调试）、**系统**（设置）。规划中的条目为禁用态并带标记，用于表达演进方向，点击不切换。

视图映射关系：

| 导航键 | 视图 | 状态 |
| --- | --- | --- |
| `chat` | 对话工作台 | 已接入 `POST /api/v1/chat`，真实模型回答，顶部可按供应商切换模型 |
| `knowledge` | 知识库管理 | 已接入 Java 业务服务，支持知识库增删改查与文档上传、列表和删除 |
| `settings` | 设置 | 外观、服务端连接、模型服务、关于 |
| `documents` | — | 未实现，禁用态 |
| `retrieval` | — | 未实现，禁用态 |

当前视图键放在 `lib/navigation.ts` 的模块级单例里（`activeNavKey` + `selectNav`），而不是 `App.vue` 的局部状态：对话页在没有可用模型时需要把用户引导到设置页，共享状态比为此引入路由更合适。侧栏开合等纯 UI 状态仍留在 `App.vue`。

## 设计令牌

颜色与圆角等语义令牌集中在 `voltmind-web/src/assets/index.css`，浅色定义在 `:root`，深色定义在 `.dark`，用 `oklch()` 书写。主色为靛蓝，用于主操作与选中态。

Tailwind CSS 4 采用 CSS-first 配置，通过 `@theme inline` 把语义令牌映射为工具类。**新增颜色需要同时修改三处**（`:root`、`.dark`、`@theme inline` 映射），否则不会生成对应工具类。

深色模式由 `useDark` 在 `<html>` 上增删 `.dark` 类驱动，用户选择写入本地存储；未显式选择时跟随系统偏好。

## 工作台背景

工作台铺一张背景图，实现在 `App.vue` 的两层固定层里：`z-0` 放背景图（`bg-cover`、不接收指针事件），其上再叠一层 `bg-background/70`（深色 `bg-background/72`）的遮罩，内容整体抬到 `z-10`。

| 决定 | 理由 |
| --- | --- |
| 用独立固定层而不是 `body` 背景 | `body` 有自己的背景色，负 `z-index` 的子元素会被它盖住；改用 `z-0` 层加 `z-10` 内容层，层级关系不依赖浏览器对负层级的绘制顺序 |
| 遮罩只淡化、不虚化 | 照片保持清晰（按使用要求），可读性靠遮罩浓度：卡片与气泡仍是 `bg-card`，长文本区域不透明；直接压在照片上的空状态文字对比度最吃紧，需要时调遮罩浓度而不是加模糊 |
| 侧栏半透明 | 侧栏原本是不透明底，改为半透明，背景才会在整个工作台连续；导航文字靠侧栏自身的浓度保持清晰 |
| 暗色下压得更重 | 照片是亮色调，暗色主题下若照透会刺眼，遮罩浓度更高 |

换图只需替换 `public/backgrounds/` 下的文件或改 `App.vue` 里的路径。当前按原图入库（约 313 KB），未做压缩与响应式裁剪。

## 品牌标识

品牌图片放在 `voltmind-web/public/brand/`，共三个文件：原始完整标识、由它派生的图形标、站点图标。

| 用途 | 使用哪个 |
| --- | --- |
| 侧栏品牌位、对话空状态 | 图形标（透明底，浅色与深色主题通用） |
| 设置页「关于」卡片 | 完整标识，置于浅色底上 |
| 站点图标 | 由图形标缩放的正方形透明底图片 |

原始品牌图有两个约束，更换品牌时必须留意：

- **背景是不透明的近白色**，直接放进深色界面会形成白色块。因此完整标识只能放在浅色底上，深色界面用透明底的图形标。
- **自带 “AI KNOWLEDGE BASE” 副标题**，缩到侧栏尺寸会糊成噪点，不适合 24–32px 的小尺寸使用。

图形标由连通域分析从原图提取：原图中图形标由两块大面积色块叠成，像素量远大于任何字母，据此把图形标与文字分开，再将近白背景按亮度转为透明。**注意图形标与文字的横坐标存在重叠**——字母 V 会落进图形标的裁剪矩形内，因此提取必须按连通域标签做掩膜，只用矩形裁切会带进字母的尖端。

## 组件契约

`src/components/ui/` 下为 shadcn-vue 组件，采用 `new-york` 风格，组件源码直接纳入仓库，可自由修改。

| 组件 | 变体 | 说明 |
| --- | --- | --- |
| Button | `default` / `outline` / `secondary` / `ghost` / `link` / `destructive`；尺寸 `default` / `sm` / `lg` / `icon` | 基于 Reka UI `Primitive`，支持 `as` 与 `asChild` |
| Card | — | 含 Header / Title / Description / Content 子组件 |
| Badge | `default` / `secondary` / `outline` / `muted` / `success` | `success` 与 `muted` 为本项目扩展 |
| Input | — | 支持 `v-model` |
| Textarea | — | 支持 `v-model`，自适应高度 |

类名合并统一走 `cn()`（`clsx` + `tailwind-merge`），组件通过 `class` 属性允许外部覆盖样式。

## 对话交互

请求链路：`ChatView` → `src/api/chat.ts` → `src/lib/http.ts`（Axios）→ `POST /api/v1/chat`。

| 状态 | 表现 |
| --- | --- |
| 发送 | 用户消息立即上屏，输入框清空，随后出现「正在思考…」气泡 |
| 请求中 | 发送按钮禁用并显示旋转图标与「发送中」，`submit` 内部再挡一次重复提交 |
| 成功 | 用模型返回的 `answer` 替换思考中气泡 |
| 失败 | 以错误气泡留在会话流中，带独立配色与警示图标，不弹窗 |
| 键盘 | `Enter` 发送，`Shift + Enter` 换行；输入法候选未结束时 `Enter` 用于确认候选，不触发发送 |
| 滚动 | 新消息后滚动到底部，用 `scrollIntoView` 交给最近滚动容器处理 |
| 长度 | 输入框 `maxlength` 与后端上限一致（2000），避免提交后才收到 422 |
| 模型 | 输入框工具行左侧的选择器按供应商分组展示已配置模型，切换后请求带上对应的两个 ID |

## 模型服务

设置页的「模型服务」卡片（`components/model-service/`）管理供应商，对话页的模型选择器与它共享 `composables/use-model-catalog.ts` 的模块级状态。

| 项 | 做法 |
| --- | --- |
| 列表 | 内置供应商只读展示，自定义供应商可编辑与删除；删除用两步确认 |
| 表单 | 供应商名 / Base URL / API Key / 模型列表（可增删行）在同一个表单里提交，模型整体替换 |
| 密钥 | 只展示后端给的脱敏串与「是否已配置」；编辑时留空表示不修改；输入框为 `password` 类型 |
| 选择持久化 | 只在内存：每次进入对话页刷新目录，选中项仍在可用列表里就保留，其余情况回退到后端默认模型或列表首项，避免选到已删除的模型 |
| 错误 | 加载失败展示错误条与重试按钮；保存失败在表单内提示，不弹窗 |

对话页的模型选择器（`components/chat/ModelSelect.vue`）用 Reka UI 的 Select 原语而不是原生 `<select>`：原生控件的下拉面板由操作系统绘制，CSS 管不到，分组、高亮与选中态都做不出与工作台一致的样式。分组、键盘导航与 ARIA 交给 Reka UI，组件里只写外观；面板固定向上展开（触发器在页面底部），选项按供应商分组，选中项用主色勾选与浅色底标识。代价是产物多打包约 84 kB（gzip 约 27 kB）。

**密钥不出前端**：API Key 只在提交请求体里出现一次，不写 `localStorage`、不进 URL、不回显；契约里也没有返回明文的字段。

限制：不做模型连通性测试（没有“测试连接”按钮），不支持非 OpenAI 兼容协议；不做流式输出（未实现 SSE），不做多轮上下文与检索引用。

## 知识库与文档交互

知识库页采用「顶部真实统计 + 左侧知识库列表 + 右侧当前库文档」结构。桌面端左右并排，窄屏上下排列；文档表格在窄屏内横向滚动，不挤压操作按钮。

| 状态 | 表现 |
| --- | --- |
| 首次加载 | 知识库和文档分别显示加载状态；请求失败显示错误与重试入口 |
| 空数据 | 未创建知识库与当前知识库无文档分别显示空状态及主操作 |
| 新建 / 编辑 | Reka UI Dialog 承载表单，名称去除首尾空格并在提交前校验必填与长度；服务端重复名称错误显示在表单内 |
| 删除 | 知识库和文档均采用页面内二次确认；确认后等待服务端完成数据库与磁盘文件清理再刷新列表 |
| 上传 | 隐藏文件输入由按钮触发；前端先校验非空、20 MiB 上限、安全文件名及扩展名，上传时禁用重复操作 |
| 成功反馈 | 创建、修改、上传和删除完成后显示页面内状态消息并刷新真实列表 |

支持 `.pdf`、`.docx`、`.md`、`.markdown`、`.txt`。客户端不提交路径，只把浏览器选择的 `File` 作为 multipart 的 `file` 字段发送，服务器生成 `storageKey`。

文档状态严格映射后端枚举：`PENDING` 为“待处理”、`INDEXING` 为“处理中”、`INDEXED` 为“已完成”、`FAILED` 为“处理失败”。R1-3 不把 `PENDING` 表达成已索引；片段数读取后端 `chunkCount`，当前解析链路未启用时显示 `0` 和“解析与向量化尚未启用”。

## 可访问性

- 侧栏用 `aside` 加 `aria-label`，导航用 `nav` 与列表结构。
- 主题切换为按钮，带 `aria-label` 与 `aria-pressed`。
- 主题选择组使用 `role="group"`，选项带 `aria-pressed`。
- 禁用导航使用原生 `disabled`，不依赖样式表达状态。
- 装饰性图标不参与可读文本。
- 对话区 `aria-live="polite"`，新消息会被读屏播报。

**已知缺口**：移动端抽屉没有实现焦点陷阱（focus trap），打开后键盘焦点仍可移到抽屉之外，关闭后也未交还触发按钮。待补。

## 与后端的衔接

前端同时连接 `ai-service/` 与 `voltmind-server/`。AI 契约见《[AI 服务接口契约](../01-架构设计/04-AI服务接口契约.md)》，Java 契约见《[Java 业务服务接口契约](../01-架构设计/05-Java业务服务接口契约.md)》。

| 用途 | 目标接口 |
| --- | --- |
| 单轮问答 | `POST /api/v1/chat` |
| 供应商增删改查 | `GET/POST /api/v1/providers`、`PUT/DELETE /api/v1/providers/{id}` |
| 可用模型列表 | `GET /api/v1/models` |
| 服务探活 | `GET /health` |
| 知识库管理 | Java `GET/POST /api/v1/knowledge-bases`、`GET/PUT/DELETE /api/v1/knowledge-bases/{id}` |
| 文档管理 | Java `POST/GET /api/v1/knowledge-bases/{id}/documents`、`GET/DELETE /api/v1/documents/{id}` |

Python 请求继续使用 `src/lib/http.ts` 与 `src/lib/api-error.ts`。Java 请求独立使用 `src/lib/business-http.ts`，统一解包 `{ code, message, data }`，把网络错误、超时、异常响应格式和已知业务错误码转换为可展示提示。两套客户端互不改写对方的 Base URL、超时和错误契约。

服务地址与超时通过 Vite 环境变量注入，**代码中不写死地址**，读取与校验集中在 `src/lib/env.ts`，变量缺失或非法时在应用启动阶段直接报错。

| 变量 | 约束 |
| --- | --- |
| `VITE_API_BASE_URL` | Python AI 服务地址，需与后端 `CORS_ALLOW_ORIGINS` 放行的前端来源配对 |
| `VITE_API_TIMEOUT_MS` | 必须大于后端 `LLM_TIMEOUT_SECONDS`，否则前端先中断，用户看不到后端的超时原因 |
| `VITE_BUSINESS_API_BASE_URL` | Java 业务服务地址，本地默认 `http://127.0.0.1:8080` |
| `VITE_BUSINESS_API_TIMEOUT_MS` | Java CRUD 与文件上传请求超时，本地默认 15 秒 |

`.env` 不含密钥、需要入库；个人覆盖写 `.env.local`（已忽略）。**禁止把 DeepSeek API Key 放进前端环境变量**——Vite 注入的变量会明文出现在浏览器产物里，密钥只由后端持有。

跨域由两个后端分别按来源白名单放行，前端不使用代理。Java 默认只放行 `http://127.0.0.1:5174` 与 `http://localhost:5174`，可通过服务端 `CORS_ALLOWED_ORIGINS` 调整，不使用全通配符。

失败提示按原因分类：超时给超时秒数，连接失败给服务地址与启动提示，后端错误状态展示 `服务返回 <状态码>：<detail>`。

## 待明确

- 视图切换用模块级共享状态实现，是否需要引入 Vue Router 取决于后续是否出现多级路由与深链接需求。
- 是否需要引入状态管理：对话状态仍在单个视图内，模型目录用模块级单例足够，暂未引入 Pinia。
- 前端目前没有单元测试框架。`src/lib/api-error.ts` 的错误分类与 `use-model-catalog.ts` 的选择回退逻辑都是纯逻辑，适合补测试，尚未补；当前靠构建检查加无头浏览器流程脚本验证。
- 模型服务缺「测试连接」能力，用户配错地址或密钥只能等到实际提问才发现。
- 文档解析、分块与向量化未实现，因此真实文档会停留在 `PENDING`，片段数为 `0`。
- 流式输出、多轮上下文、引用来源的交互形态待定。
