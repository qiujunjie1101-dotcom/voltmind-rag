## 服务范围

Python AI 服务（FastAPI）当前提供单轮问答与模型供应商管理，不含 RAG、Embedding、向量检索与业务数据存储。

对接方状态：`voltmind-web` 前端的对话页已接入 `POST /api/v1/chat`，设置页已接入模型供应商管理；Java 业务服务尚未开始。

## 接口清单

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/health` | 服务健康检查，探活与部署冒烟 |
| POST | `/api/v1/chat` | 单轮问答，按指定或默认模型调用上游 |
| GET | `/api/v1/providers` | 模型供应商列表 |
| POST | `/api/v1/providers` | 新增模型供应商 |
| PUT | `/api/v1/providers/{provider_id}` | 编辑模型供应商 |
| DELETE | `/api/v1/providers/{provider_id}` | 删除模型供应商 |
| GET | `/api/v1/models` | 可用模型列表与默认选择，供对话页模型选择器使用 |

`/api/v1/chat`、`/api/v1/providers` 需要请求体，其余无参数。

## POST /api/v1/chat

请求体：

```json
{
  "question": "什么是检索增强生成？"
}
```

带模型选择时补上两个 ID，两者必须同时提供：

```json
{
  "question": "什么是检索增强生成？",
  "provider_id": "3f1a2b3c4d5e6f70",
  "model_id": "9a8b7c6d5e4f3021"
}
```

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| `question` | string | 是 | 去除首尾空白后不能为空，最长 2000 字符 |
| `provider_id` | string | 否 | 供应商 ID，最长 64 字符，与 `model_id` 成对出现 |
| `model_id` | string | 否 | 模型条目 ID，最长 64 字符，与 `provider_id` 成对出现 |

请求体只接受上述字段，传未声明字段会被拒绝，避免参数拼错却以为生效。

**模型选择只传 ID，不传地址、密钥或上游模型名**：服务端用这对 ID 到自己保存的配置里查找，查不到就返回 400。不带模型参数时使用环境变量里的默认模型，保证既有调用方兼容。

成功响应（HTTP 200）：

```json
{
  "answer": "检索增强生成是先检索资料再生成回答。"
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `answer` | string | 模型回答，已去除首尾空白 |

## 错误码

错误响应体统一为 `{"detail": "错误说明"}`，与 FastAPI 默认结构一致。

| 状态码 | 含义 | 触发条件 |
| --- | --- | --- |
| 400 | 选择或配置非法 | 指定的供应商/模型不存在；供应商名称重复、模型 ID 重复、Base URL 指向内网、超出数量上限；编辑或删除内置供应商 |
| 404 | 供应商不存在 | 目标 ID 不在配置中 |
| 422 | 参数校验失败 | `question` 缺失、空、纯空白、超长、出现未声明字段，或模型参数只给了一个 |
| 429 | 上游限流 | 上游返回限流 |
| 502 | 上游异常 | 认证失败、连接失败、上游非 2xx、返回空回答或无候选 |
| 503 | 服务未配置 | 未选模型且未配置 `DEEPSEEK_API_KEY`，或所选供应商密钥不可用 |
| 504 | 上游超时 | 超过 `LLM_TIMEOUT_SECONDS` |

调用方按状态码分类处理：4xx 属请求问题，5xx 属服务端问题，其中 503 与 504 可重试；400 通常表示界面上的选择已失效，应刷新模型列表后让用户重选。

注意 422 的 `detail` 是数组而非字符串（FastAPI 校验错误的默认结构），与业务异常的字符串 `detail` 不同，调用方解析时需分别处理。

## 模型供应商管理

初期只支持 OpenAI 兼容协议（`protocol` 固定为 `openai`）。供应商下可挂多个模型，每个模型由「上游模型 ID + 展示名称」组成，模型条目另有服务端生成的 ID 供对话请求引用。

`GET /api/v1/providers` 响应：

```json
{
  "providers": [
    {
      "id": "builtin-deepseek",
      "name": "DeepSeek（内置）",
      "base_url": "https://api.deepseek.com",
      "protocol": "openai",
      "api_key_configured": true,
      "api_key_masked": "sk-…1a2b",
      "models": [{ "id": "deepseek-chat", "model": "deepseek-chat", "name": "deepseek-chat" }],
      "created_at": "",
      "updated_at": "",
      "is_builtin": true
    }
  ]
}
```

`GET /api/v1/models` 响应：

```json
{
  "models": [
    {
      "provider_id": "builtin-deepseek",
      "provider_name": "DeepSeek（内置）",
      "model_id": "deepseek-chat",
      "model": "deepseek-chat",
      "name": "deepseek-chat",
      "is_default": true
    }
  ],
  "default_provider_id": "builtin-deepseek",
  "default_model_id": "deepseek-chat"
}
```

`/api/v1/models` 只返回服务端确实能调用的模型：内置项要求环境变量里有 Key，自定义项要求密钥可解密。空列表表示当前没有任何可用模型，界面据此提示用户去配置。

业务规则：供应商最多 20 个，每个供应商模型最多 50 个；同一供应商内模型 ID 不能重复；展示名称留空时用模型 ID 兜底；编辑时 `api_key` 为 `null` 或缺省表示沿用已保存的密钥。

### 密钥与地址的安全约束

| 约束 | 做法 |
| --- | --- |
| 不回明文 | 响应里只有 `api_key_configured` 与 `api_key_masked`，没有任何可回显明文的字段 |
| 不落明文 | 服务端用 Fernet 加密后写入 `data/model_providers.json`，密文带 `v1:` 前缀 |
| 主口令 | 优先取环境变量 `VOLTMIND_SECRET_KEY`；未设置时本地生成 `data/.secret_key`（0600），部署环境必须显式注入 |
| 防 SSRF | 自定义 Base URL 只允许 `http/https`，禁用户名密码、查询参数与 `#` 片段；域名解析出的所有 IP 必须是公网地址，回环、私有网段、链路本地（含云元数据地址）一律拒绝 |
| 本机推理服务 | 默认被拒；需要时显式设置 `ALLOW_PRIVATE_BASE_URLS=true` |
| 调用越权 | 对话请求只传 ID，地址、密钥与上游模型名由服务端从已保存配置解析，请求方无法自带 |

已知边界：地址校验发生在保存时刻，与真实请求之间存在 DNS 重绑定窗口；更强的保证需要在 HTTP 传输层固定解析结果，当前未实现。

## 跨域策略

浏览器直连本服务需要 CORS 放行，放行名单来自配置，**不使用通配符**：接口不带 Cookie 与鉴权，通配来源会让任意站点都能读取响应，没有放行的必要。

| 项 | 值 |
| --- | --- |
| 放行方法 | `GET`、`POST`、`PUT`、`DELETE`、`OPTIONS` |
| 放行请求头 | `Content-Type`、`Accept` |
| 凭证 | 关闭（`allow_credentials=False`） |
| 预检缓存 | 600 秒 |
| 默认放行来源 | `127.0.0.1` / `localhost` 的 5174、5173、4173 |

`PUT` 与 `DELETE` 是供应商管理用的：浏览器对这两个方法会先发预检，预检不放行时请求根本不会发出，界面上的编辑与删除会静默失败。

`voltmind-web` 的 dev 端口是 5174，preview 端口是 4173，两者都在默认名单内。部署到其他域名时必须通过 `CORS_ALLOW_ORIGINS` 显式补充。

跨域下业务异常响应同样带 CORS 头，否则浏览器只能看到网络错误，读不到 429/503/504 等状态码。

前端若不使用 CORS，也可改为同源部署或由前端开发服务器代理 `/api`，两种方式后端都无需改动。

## 配置与密钥

配置读取顺序为进程环境变量、`ai-service/.env` 文件、代码内默认值。密钥只从环境读取，代码中不含硬编码，`.env` 不入库。

| 变量 | 是否必填 | 默认值 |
| --- | --- | --- |
| `DEEPSEEK_API_KEY` | 否 | 无；与自定义供应商都缺失时问答接口返回 503 |
| `DEEPSEEK_BASE_URL` | 否 | `https://api.deepseek.com` |
| `DEEPSEEK_MODEL` | 否 | `deepseek-chat` |
| `LLM_TIMEOUT_SECONDS` | 否 | `30` |
| `LLM_MAX_TOKENS` | 否 | `1024` |
| `LLM_TEMPERATURE` | 否 | `0.7` |
| `VOLTMIND_SECRET_KEY` | 部署必填 | 无；未设置时本地生成 `data/.secret_key` |
| `ALLOW_PRIVATE_BASE_URLS` | 否 | `false` |
| `DATA_DIR` | 否 | `ai-service/data` |
| `PROVIDER_STORE_PATH` | 否 | `data/model_providers.json` |
| `SECRET_KEY_PATH` | 否 | `data/.secret_key` |
| `CORS_ALLOW_ORIGINS` | 否 | 见上方跨域策略的默认放行来源，逗号分隔，去空白与重复 |

密钥只由本服务持有，任何调用方（含浏览器前端）都不应读取、保存或转发它。自定义供应商的配置与主口令放在 `data/` 下（已加入 `.gitignore`）：`.env` 描述「服务怎么跑」，`data/` 描述「用户配了什么」，两者不同步进版本库。

## 实现约定

- 模型调用封装在独立的 `ChatService`，接口层只调用 `ask(question, config)`；`config` 由 `ProviderService.resolve_chat_config` 从已保存配置解析。
- 上游异常在服务层统一翻译为业务异常，接口层不感知 OpenAI SDK 的异常类型。
- 供应商配置落在 `data/model_providers.json`，写入用「临时文件 + 原子替换」并加线程锁；当前是单机单进程，暂不引入数据库。
- 健康检查只反映进程自身状态，尚未探测 Milvus、MySQL 等依赖，后续接入依赖时再单独增加就绪检查。
- 当前为单轮问答，不保留会话上下文；流式输出（SSE）尚未实现。
