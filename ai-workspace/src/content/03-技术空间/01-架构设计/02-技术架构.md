## 架构总览

两个独立服务通过 HTTP 通信：Java 负责业务逻辑，Python 负责 AI 能力。

```text
Vue 3 + Tailwind CSS + Vite + shadcn 组件库（后期开发）
  ↓ HTTP
Java 17 + Spring Boot 3   业务服务：业务逻辑
  ↓ HTTP
Python 3.11 + FastAPI     AI 服务：AI 能力（RAG）
  ↓
DeepSeek API   Milvus   MySQL   Redis   MinIO
```

## 技术选型

| 层次 | 选择 | 职责 |
| --- | --- | --- |
| 业务服务 | Java 17 + Spring Boot 3 | 业务服务 |
| AI 服务 | Python 3.11 + FastAPI | AI 服务 |
| 环境管理 | Conda（环境名 `voltmind`） | Python 环境管理 |
| 大语言模型 | DeepSeek API | 大语言模型 |
| 向量数据库 | Milvus | 向量数据库 |
| 关系数据库 | MySQL | 业务数据 |
| 缓存 | Redis | 缓存与会话管理 |
| 对象存储 | MinIO | 文件存储 |
| 前端 | Vue 3 + Tailwind CSS + Vite + shadcn 组件库 | 后期前端开发 |

## 服务划分与通信

- Java 和 Python 采用独立服务，通过 HTTP 通信。
- Java 负责业务逻辑，Python 负责 AI 能力。
- 初期使用云端模型 API，不部署本地大模型。
- Conda 环境名统一为 `voltmind`，用于 Python AI 服务的本地开发环境。

## RAG 核心链路

RAG 包含两条核心链路：

| 链路 | 职责 |
| --- | --- |
| 文档入库 | 把资料写入知识库，供后续检索 |
| 知识检索问答 | 基于已入库资料回答用户问题 |

## 当前实现进度

Python AI 服务已落地服务骨架、健康检查与单轮问答接口，路径、参数与错误码见《[AI 服务接口契约](./04-AI服务接口契约.md)》。

Java 业务服务已完成 Spring Boot 3、MyBatis-Plus、MySQL 与 Flyway 基础工程，并提供知识库 CRUD、文档元数据管理和本地文件上传删除能力，接口见《[Java 业务服务接口契约](./05-Java业务服务接口契约.md)》。文档当前只保存原始文件并置为 `PENDING`，尚未进入解析、分块和向量化流程。

Milvus、Redis 与 MinIO 尚未接入；本地开发的文档文件由 Java 服务保存到配置目录。

## 待明确

文档入库的知识库管理、文件接收和元数据持久化由 Java 服务负责；解析、分块、Embedding 与向量写入仍待后续任务确定 Java/Python 协作契约。知识检索问答的业务编排边界也尚未确定。演进顺序见《[架构原则与演进](./03-架构原则与演进.md)》。
