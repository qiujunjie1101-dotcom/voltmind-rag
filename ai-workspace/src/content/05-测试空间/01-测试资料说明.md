## 由 QA 维护的资料

在本目录保存测试计划、功能用例、缺陷与验收报告。可复制仓库中的 `harness/templates/verification.md`，替换标题和 slug 后建立具体记录。

每次验证关联需求和业务工程 ID，记录版本、环境、操作、预期、实际结果与证据。未执行、阻塞和失败都应如实记录，不能用构建通过代替业务验收。

## Workspace 检查

```bash
npm run check
```

本命令验证 workspace 自身。业务工程的验证命令由各工程 harness 定义，具体结果通过工程 ID 和版本关联。
