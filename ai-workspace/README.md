# Ai Workspace

**ai研发知识管理空间**

一个可复制的项目级 AI 研发知识管理模板：一个项目一个 workspace，统一管理需求、设计、技术方案、测试资料、工程引用和协作记录。复制基础工程后，替换项目介绍与资料，即可为新的项目建立独立空间。

业务源码保留在独立工程，本仓库中的前端代码用于展示和编辑 workspace 资料。`code/` 维护业务工程引用，每个人通过本地配置关联自己的工程路径和角色。共享配置示例与个人配置分开维护。

## Workspace 初始化

```sh
npm ci
npm run workspace:init
# 在 code/projects.local.json 中填写空间名称和本地业务工程路径
npm run workspace:check
npm run check
```

一个空间可以引用多个业务工程，未关联时可保留空列表。初始化不会覆盖已有配置，也不会修改业务仓库。详见 [代码引用配置](code/README.md)。

复制为新项目时，排除个人配置、依赖、构建产物和旧任务执行记录，按 [模板复制说明](harness/README.md#为另一个项目复制模板) 更新品牌与项目资料。当前模板的 `code/projects.local.json` 已被 Git 跟踪；正式复用前，模板维护者需保留共享示例、设置忽略规则并取消本地配置的 Git 跟踪。仅添加 `.gitignore` 不会让已跟踪的文件停止提交。

## 页面配置入口

点击右上角“空间配置”，可管理代码引用、多选角色、查看目录约束和 harness。连接本地 workspace 后保存；不支持文件夹访问的浏览器可导入、下载 JSON。

通过 `npm run dev` 打开的配置中心还支持“授权绑定当前空间”：确认目标目录后，即使浏览器没有文件夹访问接口，也可读取、保存 `code/projects.local.json`。导入的草稿在绑定时保留，点击保存才写入；可随时解除绑定，刷新页面或重启服务后需要重新授权。该授权仅用于个人配置。“本地编辑”提供独立的文档与媒体授权；Harness 编辑继续使用浏览器文件夹授权。静态构建不包含这个本地服务。

在左侧 **空间配置 → Harness 管理** 可直接修改 Agent 工作规则、角色目录约束、协作说明和角色技能。规则默认随工程提供，页面保存写回工程文件，产品经理无需修改前端代码。

## Agent 协作与 harness

从根目录 [AGENTS.md](AGENTS.md) 开始。工作流程、资料模板、验证和交接约定见 [workspace harness](harness/README.md)。这套配置只维护 workspace 的工作边界和质量，业务工程的 harness 由各工程后续自行配置。

- 产品、视觉与技术资料：`src/content/` 既有分类。
- 测试与验收：`src/content/05-测试空间/`。
- 关联工程和外部来源：在相关资料正文中注明工程 ID、版本或来源链接，不写个人路径；有实际资料时再建立索引。
- 本地代码引用：`code/projects.local.json`，不提交、不发布到网页。
- 任务记录与可复制模板：`harness/tasks/` 和 `harness/templates/`。

## 本地运行

需要 Node.js 22.12+（或满足 Vite 7 要求的版本）。

```sh
npm install
npm run dev
```

## 构建与部署

```sh
npm run build
npm run preview
```

将 `dist/` 整体部署到任意静态托管服务。使用 hash 路由，无需服务器路由回退；相对资源路径支持子目录托管。没有后端或数据库。修改 Markdown 后需重新构建发布。

## 内容维护

在 `src/content/` 添加 Markdown，文件夹自动成为多层分类；默认按数字前缀排序，显示时会去除前缀。可按住目录或文档行上下拖拽调整同级顺序，也可从“…”选择上移、下移、置顶或置底。手动顺序保存在 `src/content/.navigation.json`，刷新、重新连接和构建后继续生效；该文件可随项目提交。文档头部支持 `title`、唯一的 `slug`、`description`、字符串 `date` 和 `status`。移动文件时保留 slug 即可保持文章链接。

正文从 `##` 开始，二三级标题生成大纲。文档间使用相对 `.md` 链接。图片放在 `public/images/`，正文引用 `./images/文件名`，该路径相对于站点入口。

详见站内「内容写作指南」。默认禁用 Markdown 原始 HTML。请勿把私人或敏感文档放进公开静态产物。

## 技术结构

- Vue 3 + TypeScript + Vite
- shadcn-vue（Reka UI）+ Tailwind CSS 4
- markdown-it + markdown-it-anchor + highlight.js
- YAML 文档元信息

`src/lib/content.ts` 负责内容解析、导航树和内部链接解析；`src/components/NavTree.vue` 提供递归目录；`src/App.vue` 提供文章导航、阅读及移动端交互。

## 当前范围

包含嵌套分类、Markdown 预览、代码高亮与复制、文章大纲、前后篇导航、文章链接、移动端目录、404 状态。文档随应用一起加载，适合初始知识规模。

初始内容说明模板自身的定位与使用方法，复制后应替换为新项目的真实需求、设计与验证记录。当前不包含团队账号、在线权限管理、实时多人协同和服务端资料存储；角色目录范围属于人和 Agent 的协作约定。

## 本地可视化维护

在左侧目录树悬停某一行，点击右侧“+”创建资料。目录下创建子项，文档旁创建同级项，顶部“文档”旁创建根目录项。选择文档或目录后，面板固定显示保存位置；创建后自动展开目标层级。触屏设备常显创建按钮。

通过 `npm run dev` 启动后，点击“本地编辑 → 授权连接当前空间”，核对目标路径并选择“允许并连接”。即使浏览器不支持文件夹选择，也可以编辑、新建 Markdown、创建目录和保存媒体。开发服务仅接受本机同源请求，授权范围限于 `src/content` 和 `public/media`；个人配置与团队规则不包含在文档编辑授权中。

在支持 File System Access API 的桌面 Chrome/Edge 中，也可选择 workspace 根目录并授权直接读写。文档写入 `src/content`，媒体以 UUID 文件名写入 `public/media`，保存前的媒体仅作为内存草稿。本地服务模式限制单个媒体 20 MiB、单次媒体总量 40 MiB、单篇 Markdown 2 MiB。

本地服务授权在刷新页面或重启服务后需重新确认；编辑期间失效或主动解除连接时保留当前草稿，重新授权后可继续保存。静态部署不包含本地服务，不支持文件夹 API 的浏览器仍可阅读。视频粘贴取决于来源应用能否提供文件，也支持直接选择文件。尺寸仅影响显示，不重采样原始媒体。浏览器授权目录会保存在本机 IndexedDB，刷新时在权限仍有效的情况下自动连接，权限过期可点击“连接已记住的项目”重新授权。

保存前比较磁盘原文，避免覆盖外部编辑。文档提交成功和读取刷新失败会分别提示。开发模式下 Markdown 热更新保留编辑器与未保存草稿。修改本地文件后，线上站点需重新构建发布。
